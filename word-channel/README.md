# word-channel (Module)

A declared table of values — bytes, ranged floats, bools — replicated to every remote client over a synced channel narrower than the table, with late-join support and a declared refresh cadence. A generator mints the controller from a word-table config (`generate.py`), so the shipped module is one worked configuration: 2 bytes + a ranged float + 4 bools (28 payload bits) over **21 synced bits**, full refresh ~0.27 s at 60 fps (one batch per 0.1 s tick plus ~1.5 sender frames, then one receiver frame).

## Provenance

The protocol is the VRCFury Parameter Compressor's (source-studied from `com.vrcfury.vrcfury`: 0.1 s batch cadence plus a guaranteed extra frame, a synced index the receiver routes on, latch double-buffering), generalized to a declared word table and hardened where the pause fixture below broke it. VRLabs **Custom-Object-Sync** (MIT, © VRLabs) is the studied ancestor whose receive-side design this entry rejects: its multi-frame receiver decode walks are the machinery a culling pause interrupts, so here every receive state decodes in one parameter-driver frame. Nothing is ported from either; both are credited as ancestors.

## Interface

- **Params in** (producer writes on the wearer; any driver, OSC, or menu source): `Pos/Hi`, `Pos/Lo` (floats holding integral 0–255), `Level` (float −1..1, quantized to 255 wire steps), `Flag/A`–`Flag/D` (bools). All unsynced — the wire below carries them.
- **Params out** (every client): the same names, driven on remotes by the receiver; `WordChannel/Cycle` (unsynced float, +1 per loop tail — the remote freshness signal, incremented by **each client's own receiver**, which is why it is unsynced by necessity: a synced copy would carry the wearer's count and prove nothing about the reader's own receiver. Its float type is an interface commitment rather than a workaround — no driver clip reaches an unsynced param, but retyping a published `globalParams` name silently breaks every OSC consumer reading it, since inbound dispatch is on the exact argument type); `Pos/Assembled` (AAP float = `Hi·256+Lo`, readable only by animator layers, one frame behind).
- **Wire** (the only synced params, all unsaved): 3 index bools + 1 8-bit int slot ×2 + 2 bool slots = 21 bits. VRCFury's Parameter Compressor (on an overflowing host avatar) never touches them: it compresses only menu-driven params (`ParameterCompressorSolverService.GetParamsToOptimize` skips any param not `usedInMenu`), so double-multiplexing cannot arise.
- **Seam**: VRCFury `FullController` on the prefab root; no scene bindings, no anchor — the module is pure animator machinery and composes anywhere under the avatar (`basis: mount-root` ↔ the FullController default `rootBindingsApplyToAvatar: 0`, vacuous while no bindings exist but recorded so a fork adding one lands in the right frame). `globalParams` exposes exactly the params named above; wire and latch params take instance prefixes.
- **Dependencies / assets**: none beyond `built/`; no menu (the channel is correctly frontless — an infrastructure module with no wearer-facing control).

## Before you compose it

- **The standalone prefab is single-instance**: the interface names are `globalParams`, so two instances collide on them. To run several channels, or to embed one inside a gimmick module, regenerate with your own word table and channel prefix and merge the emitted layers through that module's own `FullController` with only the names your module exports left global.
- **Producers write the word params, never the wire.** A wide value is split into byte words by the producer (drivers can compare and add constants but not add two params, so limb-splitting is the producer's side of the contract); consumers on the remote side reassemble with the `Pos/Assembled` Direct-tree idiom in `controller.yaml`.
- **This entry is generated output.** `controller.yaml` is written by `generate.py` from its `CONFIG` block — edit the config, rerun, recompile `built/`; never hand-edit the YAML **committed here**. The gate still holds `built/` to the committed YAML, and a regenerated YAML must be byte-identical to the committed one for the same config. That pin is about this copy: `build(config)` into your own project makes the emitted document yours, and deviating there is fine as a commented transform in your build script, never a silent edit.
- **A generator composing this channel into its own controller** calls `build(config)` instead of running the script: it returns the emitted params/layers/clips plus packing facts, and the importer owns the document frame — the contract lives in `generate.py`'s docstring, and `main()` is itself its first consumer.

## How it works

One FX layer walks a **batch counter** over the wire: the word table is chunked into batches (2 here — number slots and bool slots fill in declared order), and the sender advances one batch per 0.1 s exit-time plus one conditional-hop frame, so each batch is held a full network tick whatever the phase (the extra frame is VRCFury's guard against Unity's early exit-time quirk outrunning the tick — it costs ~1.5 frames, not one, since the hop discards the remainder an exit-time transition carries forward). The counter spans `indexLoops` full loops (2 here → period 4, 3 bits) rather than one, and 0 is reserved for "nothing sent yet". The receiver routes on the wire counter alone: from `Lost` it re-acquires only at a loop head, advances only on the exact successor value, falls back to `Lost` on any other, and increments `Cycle` at each loop tail. A dropped sync snapshot therefore costs at most one extra loop; a late joiner has the full table ~one loop after load.

Two apply disciplines exist in the generator (`atomic:`). **`set`** (shipped) latch-buffers received batches and applies the whole table atomically at the loop tail — no observer ever sees a torn set in steady state. **`batch`** applies each batch directly with no latches: the coherence unit is the batch, cross-batch values may lag each other up to one loop, and no pause-specific artifact class exists at all; its `Lost` re-acquires at any exact counter value rather than a loop head (applies are per-batch and the counter alone names the batch), so a missed sync tick costs ~one batch of staleness, not a loop. That re-acquisition also changes what `Cycle` proves: it counts loop tails under either discipline, but a `batch` receiver that entered at a tail takes its first increment one batch later — so **`Cycle ≥ 2` is the earliest reading that proves a whole table arrived**, where `Cycle ≥ 1` proves only that the wire is moving. Toggle-bus payloads want `set`; grouped measurement payloads usually want `batch`.

**The pause residual, measured.** A culled receiver's animator stops evaluating while the wire keeps updating (the view-cull half of that exposure is removable — compose `anti-cull`, one entry over; distance-hide is not defeatable), and a finite counter cannot distinguish an unbounded pause from continuous progress — so under `set`, a pause that resumes with the counter aliased (at the frozen state's own value or its successor) while frozen in a non-tail state slips **one** apply mixing whole words from the two snapshots bracketing the pause, corrected at the next apply ≤1 loop later — P ≈ (2/period)·(batchCount−1)/batchCount per resume, 1/4 in the shipped config. Emulator-measured at period 4 (av3emu, clone Animator disabled mid-transfer, words changed during the pause, 8 trials of 0.31–2.27 s): 12 applies, 9 pure, 3 whole-word mixes, **0 split words**, every trial converged. `indexLoops` divides that probability at ~1 index bit per doubling. `group:` pins words into one batch so an aliased mix can never split one value's limbs — the shipped config groups `Pos/Hi`+`Pos/Lo`, and a single-pause run of an earlier ungrouped config produced exactly the split-limb corruption the option exists to prevent (`hi` from one snapshot, `lo` from the next — a value neither snapshot ever held). A group may span number and bool words (a 12-bit value = one byte word + four bools): the packer pins both kinds to one batch index, padding bool batches forward (a padded slot is free — the wire params exist every tick regardless), and refuses when declaration order makes alignment impossible. The `batch` discipline was verified separately (5 pauses, 11 applies, 0 group splits).

Cost model, from the generator: wire bits = indexBits + 8·numberSlots + boolSlots; state count = 3·batchCount·indexLoops + 2, independent of word widths (no per-bit states anywhere); full-refresh latency = batchCount·(0.1 s + 1 frame). Slots are the bits↔latency dial — the far ends are one word per batch (minimum bits) and everything in one batch, which the generator refuses because plain synced params need no channel.

| Knob | Where | Effect |
|---|---|---|
| `batchSeconds` | `generate.py` CONFIG | seconds each batch holds; 0.1 s clears the ~12 Hz tick and 0.2 s is not needed — a bare 0.1 s sender dropped nothing in-game, empty instance or 42-player. Fall back only if a `Cycle` shortfall shows ticks being outrun |
| `numberSlots`/`boolSlots` | `generate.py` CONFIG | synced bits ↔ full-refresh latency |
| `indexLoops` | `generate.py` CONFIG | halves pause-alias probability per doubling; ~1 bit each. Inert under `atomic: batch` — there is no pause-alias artifact to divide and `Lost` re-acquires at any counter value, so widening the counter buys nothing and costs bits and states; leave it at 1 |
| `atomic` | `generate.py` CONFIG | set-atomic with declared pause residual vs batch-atomic with uniform staleness bound |

## Verifying the install

Cheapest observable: in play mode with av3emu, the runtime mirror lists the interface params under their bare names and the wire params instance-prefixed (`VF##_WordChannel/Wire/…`) with `synced=True`; spawn a remote clone, write any word on the local, and the clone's copy follows within ~0.5 s with `WordChannel/Cycle` climbing ~3.5–4.5/s (one per loop; frame-rate-dependent — ~4.3/s at 60 fps, ~3.75/s at 30 fps). A `Cycle` frozen at 0 on the clone means the receiver never left `Lost` (wire params not actually synced — check the params asset landed); bare interface names missing means the `globalParams` list was edited or the module was merged through a foreign controller that re-prefixed them. One liveness precondition rides the receiver: it advances only on exact successor counter values, so a client whose frame interval approaches the ~0.117 s batch hold (under ~10 fps) skips codes, falls to `Lost` often, and degrades to sporadic applies — declared, not measured.

What the emulator structurally cannot show for this entry: real network snapshot loss (av3emu's sampler is lossless — the `Lost` path is exercised only by the induced-pause fixture), and the shipping client's parameter delivery to a distance-hidden avatar's paused animator — the emulator models it as "wire updates, animator doesn't", the design is correct under either delivery semantics, but the in-game alias rate is unmeasured. The two-client check, when wanted: wear it, have the second client distance-hide and unhide the wearer mid-change, and confirm the words converge within a second of unhide with no stale mixed readings persisting. In-game, a `Cycle` rate persistently below the nominal ~1/cycle-time is the miss-rate meter — each sync tick the sender outruns sends receivers through `Lost`.
